## 17-A. F-58. AI 어시스턴트 (Claude API 연동)

### 개요
Anthropic Claude API(`claude-opus-4-8` / 경량 작업은 `claude-haiku-4-5`)를 백엔드에서 호출하여
축적된 업무·댓글·채팅·결재 데이터를 요약·생성·검색한다. **로컬 전용 원칙 유지** — API 키는
`backend/.env`(`ANTHROPIC_API_KEY`)에만 저장, 클라이언트로 노출 금지. 모든 AI 호출은 백엔드 프록시 경유.

### 세부 기능
1. **AI 업무 자동 생성** — 자연어 입력 → 업무 초안(제목·설명·담당자 후보·기한·우선순위) 배열 반환.
   사용자가 검토·수정 후 확정 생성. 담당자는 이름 매칭으로 후보만 제시(자동 배정 금지).
2. **AI 주간/일일 요약** — 기간 내 `task_histories`·`time_entries`·활동로그를 집계 후 요약 리포트 생성.
   개인용/팀용/관리자용 스코프. 스탠드업용 마크다운 출력.
3. **채팅/회의 요약 + 액션아이템 추출** — 선택한 채팅방 메시지 범위 또는 회의록(F-61) → 요약 + 할 일 후보.
   추출된 액션아이템은 원클릭으로 업무(F-03) 생성.
4. **시맨틱 검색(Ctrl+K 확장)** — 임베딩 기반 의미 검색. 초기 버전은 키워드+AI 재순위(rerank)로 시작,
   추후 pgvector 도입 가능(설계만 반영).
5. **결재/메일 초안 보조** — 결재 본문·메일 본문 AI 초안 버튼. 스트리밍 응답.

### DB 스키마 (Prisma)

### API
- `POST /api/ai/tasks/generate` — { prompt } → 업무 초안 배열
- `POST /api/ai/summary` — { scope, from, to } → 요약 리포트
- `POST /api/ai/chat/summarize` — { roomId, fromMsgId?, toMsgId? } → 요약 + 액션아이템
- `POST /api/ai/draft` — { type: 'approval'|'mail', context } → 초안 (스트리밍, SSE)
- `GET /api/ai/search?q=...` — 시맨틱 검색 (기존 `/api/search` rerank 확장)
- `GET/POST /api/ai/conversations`, `GET /api/ai/conversations/:id` — 대화 이력
- `GET /api/admin/ai/usage` — 사용량/비용 (관리자, `AI_USAGE` 권한)

### 보안 · 운영
- **PII 가드 연동(F-56)**: AI로 보내기 전 `piiGuard`로 주민번호·카드번호 등 마스킹.
- **감사로그**: `AUDIT_ACTION`에 `AI_REQUEST` 추가, 프롬프트는 마스킹본만 기록.
- **권한/쿼터**: 관리자가 사용자별 일일 토큰 쿼터 설정(`AppSetting`). 초과 시 차단.
- **모델 선택**: 요약·검색 재순위는 haiku, 생성·초안은 opus 기본(설정에서 조정).

### 파일

- `backend/src/controllers/aiController.js`, `routes/ai.js`
- `frontend/src/api/ai.js`, `frontend/src/components/ai/AiPanel.jsx`(우측 슬라이드 패널),
  `AiTaskGenerator.jsx`, `AiSummaryButton.jsx`, `store/aiStore.js`

## 18-A. F-59. 협업 위키/문서 (Docs)

### 개요
팀 지식베이스·회의록·매뉴얼·정책 문서를 계층 구조로 작성·공유. 개인 메모지(F-47)와 달리 **팀 공유·권한·버전**을 갖춘다.
블록 기반 리치 에디터(제목·리스트·표·코드·체크박스·이미지·파일 임베드). 문서 간 링크(`[[문서명]]`)와
업무/결재/보드 카드 멘션 지원.

### 세부 기능
- 문서 트리(스페이스 → 폴더 → 문서, parentId 자기참조), 드래그 재정렬
- 권한: 공개(전체)/부서·팀/특정 멤버, 읽기/편집 구분
- 버전 이력 & 롤백(플레이북 버전 패턴 재사용), 변경 diff
- 실시간 공동 편집(Socket.IO doc 룸) — 초기엔 "편집 중" 표시 + 마지막 저장자 잠금, 추후 CRDT
- 댓글(블록 단위 인라인 코멘트), @멘션(F-50 연동), 첨부
- 템플릿(회의록/제안서/정책) 제공, 즐겨찾기, 전역 검색(F-49) 색인 포함
- 문서 → 업무 전환, 회의록(F-61)과 양방향 연결

## 19-A. F-60. OKR / 목표 관리

### 개요
분기·연간 목표(Objective)와 핵심결과(Key Result)를 정의하고, KR에 업무(Task)·보드카드·WBS를 연결해
진척률을 자동 집계. 회사 → 부서/팀 → 개인 계층으로 목표 정렬(alignment) 표현.

### 세부 기능
- 목표 주기(OkrCycle): 연도·분기(2026-Q3 등), 기간
- Objective: 소유자·범위(회사/부서/팀/개인)·상위 목표 정렬(parentId), 상태(on_track/at_risk/off_track)
- Key Result: 측정 유형(수치/퍼센트/완료여부), 시작값·목표값·현재값, 자동/수동 진척
- KR ↔ 업무/카드/WBS 연결 → 연결 항목 완료율로 KR 자동 진행률 계산
- 체크인(주간): 현재값·신뢰도·코멘트 기록(히스토리)
- 대시보드: 목표 트리, 진척 히트맵, 위험 목표 하이라이트

### DB 스키마
```prisma
model OkrCycle {               // okr_cycles
  id        Int      @id @default(autoincrement())
  name      String   // '2026 Q3'
  startDate DateTime
  endDate   DateTime
  isActive  Boolean  @default(true)
  objectives Objective[]
}

model Objective {              // objectives
  id         Int      @id @default(autoincrement())
  cycleId    Int
  parentId   Int?     // 상위 목표 정렬
  title      String
  description String?  @db.Text
  scope      String   // company | dept | team | personal
  scopeRefId Int?     // 부서/팀 id (scope에 따라)
  ownerId    Int
  status     String   @default("on_track")
  progress   Int      @default(0) // 0~100 (KR 가중 평균)
  delYn      String   @default("0") @db.Char(1)
  createdAt  DateTime @default(now())
  cycle      OkrCycle @relation(fields: [cycleId], references: [id])
  keyResults KeyResult[]
}

model KeyResult {              // key_results
  id           Int      @id @default(autoincrement())
  objectiveId  Int
  title        String
  metricType   String   // number | percent | boolean
  startValue   Decimal  @default(0) @db.Decimal(14, 2)
  targetValue  Decimal  @db.Decimal(14, 2)
  currentValue Decimal  @default(0) @db.Decimal(14, 2)
  autoProgress Boolean  @default(false) // 연결 항목 완료율로 자동 계산
  ownerId      Int?
  objective    Objective @relation(fields: [objectiveId], references: [id], onDelete: Cascade)
  links        KeyResultLink[]
  checkins     KeyResultCheckin[]
}

model KeyResultLink {          // key_result_links
  id          Int    @id @default(autoincrement())
  keyResultId Int
  refType     String // task | board_card | wbs_task
  refId       Int
  keyResult   KeyResult @relation(fields: [keyResultId], references: [id], onDelete: Cascade)
}

model KeyResultCheckin {       // key_result_checkins
  id          Int      @id @default(autoincrement())
  keyResultId Int
  value       Decimal  @db.Decimal(14, 2)
  confidence  Int?     // 1~10
  comment     String?
  createdBy   Int
  createdAt   DateTime @default(now())
  keyResult   KeyResult @relation(fields: [keyResultId], references: [id], onDelete: Cascade)
}
```

### API
- 주기: `GET/POST /api/okr/cycles`, `PUT/DELETE /api/okr/cycles/:id`
- 목표: `GET /api/okr/objectives?cycleId=`, `GET/POST /api/okr/objectives`, `PUT/DELETE /api/okr/objectives/:id`
- KR: `POST /api/okr/objectives/:id/key-results`, `PUT/DELETE /api/okr/key-results/:krId`
- 연결: `POST/DELETE /api/okr/key-results/:krId/links`
- 체크인: `GET/POST /api/okr/key-results/:krId/checkins`
- 대시보드: `GET /api/okr/tree?cycleId=`

### 파일
- `controllers/okrController.js`, `services/okrProgressService.js`(자동 진척 집계), `routes/okr.js`
- `pages/Okr/*`(트리 뷰, 목표 상세, 체크인 모달), `components/okr/OkrTree.jsx`

## 20-A. F-61. 회의 관리 (Meetings)

### 개요
일정(F-55)의 회의 유형을 확장해 **안건 → 회의록 → 결정사항 → 액션아이템** 라이프사이클을 관리.
회의 종료 후 액션아이템을 업무(F-03)로 전환하고, 결정사항을 결재(F-52)·위키(F-59)로 연결.
AI(F-58)로 회의록 요약·액션아이템 자동 추출 가능.

### 세부 기능
- 회의 생성: 제목·일시·장소/자원(F-55 resource 연동)·참석자(내부/외부)·주최자
- 안건(agenda) 목록: 순서·발표자·소요시간·첨부
- 참석자 상태: 초대/수락/거절/참석/불참, 알림 발송(F-10/SSE)
- 회의록: 리치 텍스트(위키 에디터 재사용) + 결정사항·액션아이템 구조화
- 액션아이템: 담당자·기한 → 원클릭 업무 생성(taskId 연결), 상태 추적
- 반복 회의(주간 정례 등), 이전 회의 회의록 자동 참조
- 결과 배포: 참석자·부서에 회의록 메일(F-54)/알림 발송

### DB 스키마
